# Codex 바이브코딩 전달 문서 — CPU 전용 내검 규칙 탐색기 개선

## 목적

첨부 가구생활조사 CSV의 **범주형 IF–THEN 규칙, 숫자 구간 규칙, 산술식 F(X)=Y, 코드 매핑, 위반 데이터**를 CPU만으로 자동 발굴·검증하는 범용 라이브러리로 개선한다. 신뢰도·지지도·lift·예외 건수·검증셋 적합도를 기록하고, 사용자가 승인한 규칙만 운영 시스템에 반영한다.

현재 실행 결과는 `results/ANALYSIS_REPORT.md`, `results/rules.json`, `results/violations.csv`에 있으며, 소스는 `rule_miner.py`이다. 최소 예시는 `cpu_minimal_example.py`이다.

## 절대 제약

1. LLM 호출, 생성형 AI 추론, 딥러닝 모델, GPU, PyTorch/TensorFlow, 외부 API/인터넷 의존을 **사용하지 말 것**.
2. Python 3.10 이상, Windows 10/사내망, CPU만 가정. 최소 검증기는 Python 표준 라이브러리로 동작해야 함.
3. NumPy/Pandas도 CPU 처리로만 사용하고, 선택적으로 표준 라이브러리만 쓰는 모드를 유지.
4. 원본 CSV/DB의 입력값을 직접 UPDATE/DELETE하지 않음. 규칙 후보와 위반사항은 별도 출력·저장.
5. 조사표 코드북·업무 규칙이 없는 상태에서 발견된 관계를 '공식 내검 규칙'으로 자동 확정하지 않음.

## 현재 실제 수행 로직

| 단계 | 수행 알고리즘 | 주요 산출정보 |
|---|---|---|
| A. 형식 점검 | CSV 인코딩, 열별 고유값 수/결측, 숫자 타입 | 원본 열 목록, 결측 수 |
| B. 조건식 후보 | 각 선행범주별 그룹 빈도·최빈 후행값, 그룹별 최소 표본수 필터 | `IF A=a THEN B=b`, support/confidence/lift |
| C. 다중코드 매핑 | `groupby(A)[B]` 최빈 사전 | 매핑테이블, 예외 |
| D. 수치 구간 | 정렬된 X에서 연속 K개 구간 최빈값 불일치 합 최소화, 동적계획법 | 연령구간, 가구원수구간 경계값 |
| E. 산술식 후보 | 자동 스캔 `aX`, `X±Y`, `X/Y`, `100X/Y`, `X/√Y` + 합계 후보 | 항목별 수식, 허용오차, 위반 |
| F. 구간별 세율 | `세금/소득` 비율을 세 연속 구간으로 분할, 잔차제곱합 최소화 전수탐색 | 경계 300/600만원, 세율 5.5/10.5/17% |
| G. 검증 | 학습 1,125행/보류 검증 375행, 각각 신뢰도·예외 건수 | `rules.json`/`violations.csv` |

## 구현 개선 우선순위

### P0. 재현성·정확성

- `rule_miner.py`에서 상수로 들어간 경제 도메인 수식은 JSON/YAML **수식 후보 설정**으로 외부화. 문자열 평가 `eval()` 사용 금지. 허용된 연산자만 파싱하는 AST 인터프리터를 설계.
- 기본 합계는 합계 대상이 모두 존재할 때만 계산; 결측을 0으로 치환하지 말 것. 0 소득 분모, 음수 분모, 소수점 경계(29.5/39.5·299/300/599/600) 단위 테스트.
- 세율 탐색을 일반 `Y = piecewise(a_i*X+b_i)`까지 확장하되 CPU 동적계획법/그리드 탐색으로 구현. 검증표본에 나타나지 않은 경계는 **미검증 구간**으로 표시.
- 조건식은 연역 규칙과 경험적 상관관계의 차이를 화면/DB에 명확하게 표시. 고유 ID/날짜/메모 등 의미 없는 변수는 탐색에서 제외.
- 매핑 규칙에 등장하지 않은 새 코드는 `UNKNOWN`/검토대기로 남기고, 무조건 최빈 코드로 강제 변환하지 말 것.

### P1. 통계와 성능

- 지지도 전체분모/조건분모 구분, 신뢰도, lift, conviction, Wilson 95% 신뢰구간, 다중 비교 FDR 등 보고.
- 임의 행 분할 외에 조사구(`표본조사구코드`), 시도, 연도별 그룹 홀드아웃을 추가해 지역·시점 누설을 통제.
- 대규모(예: 50만 행 × 500열) 처리 시 열 cardinality 메타필터, 독립 병렬 CPU 작업, chunked CSV/DB cursor, 후보 캐싱, O(N²) 조합 제한. 정확도를 해치지 않는 속도 개선을 벤치마크.
- 순서 바꾸기·중복행 주입·미지 코드·결측·새 연도·데이터 타입 혼합 시 결과가 안정적으로 유지되는지 회귀 테스트.
- 희소한 2~3조건 규칙을 무작정 채택하지 않도록 최소 표본·독립 검증 개선폭 제한. 기본은 단일 조건으로 유지.

### P2. INIT 데이터 내검 시스템 연계

- Python 라이브러리를 `profile`, `discover_conditions`, `discover_formulas`, `validate`, `export` 모듈로 분리. 스케줄러/CLI REST API에서 재사용.
- 발견 후보 레포지토리(예: `RULE_CANDIDATE`)와 승인 규칙(`RULE_APPROVED`), 실행 위반(`RULE_VIOLATION`)의 단계를 구분. 기존 `C##INITAI` 스키마/`ECON_AR_RULES_FINAL`/`ECON_VIOLATIONS`와 직접 일괄 합치지 말고 실제 DDL 확인 후 매핑.
- Oracle 21c/12c 호환을 위한 바인드 변수·배치 적재·한글 문자열 인코딩·소수점 처리. 내부 DB 사용자 권한·트랜잭션 경계 유지.
- 규칙 설명, 대상 컬럼 ID, 연산자/임계값, 분모, 수치 허용오차, 검수자 승인 상태, 모델/알고리즘 버전, 원본 해시, 검증 기간, 위반 행의 PK 저장.
- 시각 UI: 규칙별 (전체/학습/검증) 신뢰도, 적용 건수, 위반 샘플 20건, 승인/거절, 재실행, 승인된 규칙만 내검 반영.

## 반드시 통과할 수용 테스트

1. 원본 샘플에서 `월총소득 합계`는 **1469/1500**, `연간소득` **1476/1500**, `월총지출` **1472/1500**, `월저축액` **1475/1500** 재현.
2. `가처분소득/가구원수`는 허용오차 0.051에서 **1500/1500**, `가처분소득/√가구원수`는 **1479/1500** 일치.
3. 구간 세율은 원천 소득합계 기준 **300/600만원 경계·5.5/10.5/17%**를 찾아 **1500/1500** 일치.
4. 연령구간 코드 **1482/1500**, 가구원수구간 **1478/1500**, 시도코드↔시도명 매핑 **1479/1500** 일치.
5. 샘플에서 주거비부담률 `100×주거비/max(가처분소득,1)` **1480/1500** 일치 (0 소득 2건 포함).
6. 동일 시드/입력 파일에서 `rules.json` 결과가 결정적으로 일치. 다른 CSV에도 열 매핑을 변경하면 재실행 가능.
7. 외부 연결을 차단한 Windows 사내망에서 표준 라이브러리 최소 검증기가 **그대로 실행**. GPU/AI 패키지 설치 없이 NumPy/Pandas 발굴기 실행.
8. 발견 단계에서 **사용자 원본 파일은 한 바이트도 수정되지 않아야 하며**, 승인 전 규칙은 운영 내검 대상에서 제외.

## Codex에 요청할 구현 지시문

> 이 폴더 전체를 프로젝트로 읽고, `README.md`, `results/ANALYSIS_REPORT.md`, `results/rules.json`, `rule_miner.py`, `cpu_minimal_example.py`의 실제 실행결과를 기준으로 개선하라. 기본 요구는 **CPU에서 실행되는 설명 가능한 규칙 채굴 알고리즘**이며 AI 모델 추론과 GPU는 금지한다. 먼저 재현 테스트를 통과시킨 뒤, P0→P1→P2 순서로 각 기능의 구체적 근거·성능 측정·안전한 마이그레이션 전략을 제시하고 단계적으로 구현하라. 원본 데이터/운영 DB에 대한 수정은 실행하지 말고 별도 승인을 받도록 설계하라.
