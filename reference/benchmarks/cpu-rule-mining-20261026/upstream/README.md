# 국가통계 가구생활조사 규칙 발굴·검증 (CPU 전용)

이 파일 묶음은 가구생활조사 CSV에서 **IF–THEN 연관/내검 규칙**과 **F(X)=Y 계산 규칙**을 발굴하고, 기존 행을 변경하지 않은 채 위반 내역을 CSV로 출력합니다. 모든 코드는 로컬 CPU에서 실행되며 LLM API, GPU, AI 모델 학습·추론, 외부망 연결을 사용하지 않습니다.

## 1. 폴더 구성

| 파일 | 용도 |
|---|---|
| `cpu_minimal_example.py` | 외부 패키지가 전혀 없는 Python 표준 라이브러리 예제. 발견된 규칙 검증에 사용 |
| `rule_miner.py` | 규칙 자동 발굴+검증 엔진. NumPy/Pandas로 CPU 통계/전수탐색/동적계획법 실행 |
| `data/국가통계_가구생활조사_샘플.csv` | 사용자가 제공한 원본 (수정 없음) |
| `results/ANALYSIS_REPORT.md` | 원본 1,500건에 대한 분석 결과 및 계산방법 |
| `results/rules.json` | 규칙 정의, 입력/목적 필드, 각 규칙별 적용·일치·위반 건수, 분리검증 결과 |
| `results/violations.csv` | 위반 규칙 ID별 원본 CSV 행번호, 가구식별번호, 실제/기대값 |
| `results/flagged_households.csv` | 위반 가구 ID별로 중복 제거한 목록 |
| `results/screened_formulas.json` | 자동 산술 탐색에서 발견한 추가 수식 후보, 공식 검증 규칙과 구분 |
| `results/run_metadata.json` | 실행환경 파라미터와 원본 SHA-256 검증값 |
| `test_rule_miner.py` | 재현 검증용 자동 테스트 |
| `CODEX_HANDOFF.md` | Codex에게 그대로 전달할 개선 과제·수용 기준 |

## 2. 가장 간단한 실행 (Python만 설치)

Windows 10의 PowerShell 또는 VS Code 터미널에서 압축을 푼 폴더로 이동한 뒤:

```powershell
py -3 cpu_minimal_example.py --input "data/국가통계_가구생활조사_샘플.csv" --output "results/minimal_violations.csv"
```

이 소스는 이미 발굴된 9개 숫자 수식과 주요 IF–THEN 규칙을 원본 전체에 적용하는 **검증기**입니다. `csv`, `math`, `collections` 등 표준 라이브러리만 사용합니다. 입력 데이터는 고치지 않으며 결과만 별도 파일에 씁니다.

## 3. 자동 발굴 엔진 실행 (CPU NumPy/Pandas 사용)

```powershell
py -3 -m pip install -r requirements.txt
py -3 rule_miner.py --input "data/국가통계_가구생활조사_샘플.csv" --output "results"
py -3 -m unittest -v test_rule_miner.py
```

내부망 환경에서는 필요한 `numpy`, `pandas` wheel 파일만 미리 준비하면 네트워크 연결 없이 실행할 수 있습니다. 프로그램 자체에는 인터넷 호출이 없습니다. `scikit-learn`, PyTorch, TensorFlow, 클라우드 LLM 도구는 **필요하지 않습니다**.

자동 발굴 로직:

1. **IF–THEN**: 값별 그룹화 `groupby` → 최빈 후행값 → 조건 적용건수, 지지도, 신뢰도, lift 산출 → 분리 검증.
2. **코드 매핑**: `시도코드 → 시도명`처럼 원인 필드의 값별 최빈 결괏값으로 사전(`dict`) 작성 → 다른 행에서 검증.
3. **수치구간**: 연령대·가구원수구간의 경계를 CPU 동적계획법으로 탐색. 연속 구간별 오분류 건수의 합을 최소화.
4. **기본 수식**: 합계/차/배수/나눗셈/제곱근의 후보를 생성하고 값과 비교. 불일치 행만 추출.
5. **세율 수식**: 총소득과 4개 원천소득합 중 기준변수를 비교하고, `세금 / 기준소득` 비율을 오차제곱합이 작은 **연속 3개 구간**으로 전수탐색. 각 구간 세율의 중앙값을 검증.
6. **과적합 방지**: 원본 ID·날짜·메모 제외, 적용 건수 및 lift 하한, 학습 75%/검증 25% 분리(시드 42).

설정 예시:

```powershell
py -3 rule_miner.py --input "data/국가통계_가구생활조사_샘플.csv" --output "results" --min-support 40 --min-confidence 0.97 --min-validation-confidence 0.95 --min-lift 1.25 --max-if-rules 50
```

`--max-antecedents 2`를 지정하면 일부 2개 조건 조합도 시범 탐색합니다. 기본값 1은 희소 조합의 우연한 100% 일치를 줄이기 위해 선택했습니다.

## 4. 검증값을 해석할 때 주의

- **수식 일치율 100% = 실제 통계청 공식 규칙이라는 뜻은 아닙니다.** 이 샘플 데이터에 대한 계산적 관계입니다.
- IF–THEN 신뢰도 분모는 전체 1,500건이 아니라 **선행조건을 만족하는 행 수**입니다. 지지도·lift·검증셋 신뢰도를 함께 살펴야 합니다.
- 소수점 한 자리로 기록된 나눗셈/비율은 부동소수점 반올림 차이를 고려하여 절대오차 0.051을 허용합니다. 일반 합계·세율 계산은 기본적으로 엄격 비교합니다.
- `주거비부담률`에서 가처분소득이 0인 행도 존재하며, 샘플 값은 분모를 최소 1로 두는 형태와 일치합니다. 정책적으로 적절한 값인지 별도 검토가 필요합니다.
- 결측은 0이 아닙니다. `산업분류`, `통근시간_분`, `주당근로시간`의 비입력 상태는 별도 범주로 관리합니다.
- 규칙 위반 하나가 연쇄적으로 여러 수식에 영향을 줄 수 있으므로, 위반 **가구 수**와 위반 **규칙 건수**를 따로 봅니다.
- 이 데이터는 원본 순번에 특정 주기의 예외가 섞인 형태를 보이나, 코드에서는 행번호·가구식별번호를 예측조건으로 사용하지 않았습니다.

## 5. 운영 시스템에 반영할 때

INIT Data Editing System 등에 적용할 경우 규칙 후보 자동 발굴 → 샘플 외 검증 → 검수자 승인 → 규칙 레포지토리 반영 → 원본 대상 위반 탐지의 단계로 분리할 것을 권장합니다. `CODEX_HANDOFF.md`에 Oracle 21c 연계 및 대용량·범용화를 위한 개선 요구와 테스트 조건을 정리했습니다.
